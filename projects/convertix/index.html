Overview / 01

The problem,the idea.

A Flutter media and document conversion app for Android and iOS. Media processing is performed on-device without internet, while document conversion runs through a FastAPI and LibreOffice backend.

NoteCurrent documentation identifies Play Store signing and Android API 36 requirements as blockers before the next release.

Architecture / 03

Systemswith a point.

Media tools process files on-device. Document tools use a separate FastAPI and LibreOffice service. These are alternative processing branches, with results recorded in local conversion history.

SPEC-CVX // HYBRID ENGINEILLUSTRATIVE MODEL

A documented system model. Walkthroughs are illustrative; they do not contact or verify a live service.

Topology

  • Flutter Application → On-Device Media Engine: Local media processing
  • Flutter Application → Cloud Document Worker: Remote document processing
  • Flutter Application → Local Hive Persistence: Save result metadata
CLIENT / STATE CORE

Flutter Application

Flutter + Riverpod

AsyncNotifier architecture manages conversion queues, cancel tokens, format validations, and batch progress tracking without UI blocking.

InterfacePlugin calls / HTTPS
DesignAsynchronous task state

Example event: Task created: video transcode job queued -> analyzing codec header

LOCAL RUNTIME / ZERO NET

On-Device Media Engine

FFmpegKit + Dart image tools

FFmpegKit handles audio/video conversion and compression, while Dart image tools handle image operations. Processing time and available codecs depend on the device and build.

InterfaceFlutter plugin / local I/O
DesignOffline media processing

BACKEND / DOCUMENTS

Cloud Document Worker

FastAPI + Headless LibreOffice

FastAPI invokes document tools including headless LibreOffice and PyMuPDF. The supplied architecture specifies deletion within 30 seconds; this portfolio does not verify the deployed service's retention behavior.

InterfaceHTTPS / Multipart REST
DesignTemporary document processing

Example event: Doc worker: multipart received -> LibreOffice headless render complete

Pipeline

01

Format Inspection

Client validates file MIME type and routes to local or cloud engine.

02

Local Media Branch

Media tools process supported formats on the device without uploading media to the document service.

03

Document Branch

Document tools send supported inputs to FastAPI and LibreOffice instead of the local media engine.

04

Result and History

The client receives the result and stores history locally. Backend cleanup follows the documented retention design.

Decisions

Zero-Data Media

Media never leaves phone: 100% offline FFmpeg

Temporary Documents

The backend design specifies short-lived processing files

Async State

Riverpod AsyncNotifier with job cancel tokens
