Overview / 01

The problem,the idea.

A mobile-first meme delivery product built around a single-action capsule rather than an infinite feed. The product pairs a public web platform and Android app with serverless edge delivery and a curation system.

Architecture / 03

Systemswith a point.

A gesture-driven client uses a rolling prefetch queue to reduce waiting while Cloudflare handles content delivery. The supplied mobile v3.4 snapshot describes React 19, Capacitor 8, and a 12-item queue target; the separate web frontend uses React 18. Queue depth varies during use.

Topology

  • Android & Web Client → Client Prefetch Queue: Consume queued cards
  • Client Prefetch Queue → Cloudflare Edge Gateway: Request replenishment
  • Cloudflare Edge Gateway → Cloudflare D1 & R2: Query metadata and media
FRONTEND / UI

Android & Web Client

React / Capacitor 8 on Android

The Android client uses React 19 and Capacitor 8; the web frontend uses React 18. A native MediaStore bridge supports saving images, alongside a local vault and mood boards.

InterfaceHTTPS + Android Java bridge

NETWORK / ROUTER

Cloudflare Edge Gateway

Pages + Workers Runtime

Cloudflare Pages Functions query curated content and handle client events. Backend engineering and curation are separate from Pratham's frontend and native-client role.

InterfaceHTTPS / Pages Functions
DesignServerless content API

DATA / MEDIA LAKE

Cloudflare D1 & R2

Serverless SQLite + R2 Bucket

D1 stores structured metadata and curation state; R2 stores media objects. The client receives eligible media through the delivery API.

InterfaceS3 API + SQL Prepared Stmt
DesignMetadata and media separated

PIPELINE / BUFFER

Client Prefetch Queue

Async client-side fetching

The supplied v3.4 mobile snapshot targets a 12-item FIFO queue and replenishes it during consumption. This is a buffering strategy, not a guarantee of zero latency or uninterrupted connectivity.

InterfaceMemory Queue Buffer
Design12-item rolling queue target
